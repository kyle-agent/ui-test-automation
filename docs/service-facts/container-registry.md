# Container Registry: 접근 제어(IP ACL) 수정 경로와 KI-001 (2026-10-16, 에이전트 B)

`scenarios/container/container-registry.yaml` steps[2]·[4] 와 `data/ui-operations.yaml` scr 절의 근거. 2026-10-07(6D) 에 "연필이 열리지 않음 / 확인 못 함" 으로 적은 `updateprivateacl` · `updatepublicacl` 을 다시 프로브했다.
프로브(레지스트리 1개 생성 → 조사 → 해지, 쿼터 1 이라 목록이 비어 있을 때만): `test-results/encode-test/agentB-scr-probe*.ts`(gitignore), 로그 `reports/agentB-probe-scr*-20261016.log`.

## 1. 상세 화면 `#/scr/registry/detail/info?containerRegistryId=…`

- 상단 버튼 "이용 가이드 · 서비스 해지". 연필(i.i-edit) 라벨: 엔드포인트 · **프라이빗 엔드포인트 접근 제어** · (퍼블릭을 켠 동안) **퍼블릭 엔드포인트 접근 제어** · 가시성.
  접근 제어 라벨 둘은 `<span class="info"><i class="i-info">…<svg>` 안내 아이콘이 연필 앞에 함께 있다 → `.scp-form-group-label` 의 textContent 가 라벨 글자만이 아니어서
  **`^\s*라벨\s*$` 정규식(detail-edit.ts `label()` 의 문자열 인자)으로는 못 찾는다**. 6D 의 "연필이 열리지 않음" 은 빈 로케이터를 30초 기다린 것.
  또 라벨 글자 사이 공백이 일반 공백이 아니라서(2026-10-20 프로브: `hasText: '프라이빗 엔드포인트 접근 제어'`(문자열, 공백 정규화)는 맞고 `/프라이빗 엔드포인트 접근 제어/` 는 0개, 10-16 spec 2회 실패 "값이 60초 안에 바뀌지 않았습니다. 마지막: (빈 값)" 의 원인)
  RegExp 는 단어 사이를 `\s*` 로 잇는다: `/프라이빗\s*엔드포인트\s*접근\s*제어/`, `/퍼블릭\s*접근\s*허용\s*IP/`. 이 RegExp 를 넘기면 `openLabelEdit`·`detailValue`·`waitDetailValue` 모두 동작한다.
- 값 구조: "프라이빗 엔드포인트 접근 제어 = 사용" 아래 "프라이빗 접근 허용 리소스 총 0 서비스 | 리소스명" 표(라벨 "프라이빗 접근 허용 IP" 는 숨김), 퍼블릭도 같은 꼴 + "퍼블릭 접근 허용 IP 총 N <IP…>".

## 2. 프라이빗 엔드포인트 접근 제어 수정 (updateprivateacl)

- 연필 → 모달 "프라이빗 엔드포인트 접근 제어 수정": 안내("사용 설정하면 추가한 리소스의 접근만 허용… 사용 설정하지 않으면 동일 '리전'에 속한 모든 서브넷 상의 리소스에 대한 접근을 허용"),
  "사용" 체크(`.scp-select`), "프라이빗 접근 허용 리소스" 표(5개씩 보기 · "추가") → 확인 → "수정한 정보를 저장하시겠습니까?" → `PUT /console/api/scr/v1/container-registries/{id}/private-acl`.
- "사용" 을 끄고 확인하면 알림 **"프라이빗 엔드포인트 접근 제어 사용을 해제하시겠습니까? 프라이빗 엔드포인트 접근 제어 사용 해제 시, 레지스트리가 SCP내 다른 리소스에 노출될 위험이 존재합니다. …"**(취소/확인) 가 먼저 뜬다(2026-10-20 실측).
  이 알림은 DOM 에서 수정 모달보다 앞에 놓여 `saveModal`(마지막 모달부터 봄)이 수정 모달의 "확인" 만 되풀이 눌러 90초를 넘겼다 → spec 은 알림을 문구(`/해제하시겠습니까|저장하시겠습니까/`)로 찍어 누른다(`saveAclModal`).
- 생성 직후 기본값은 **사용 + 허용 리소스 0개**. 허용 리소스 없이도 사용 ↔ 미사용 전환이 저장된다(spec steps[2]: 사용 → 미사용 → 사용). 허용 리소스 "추가" 는 VPC 자원 선택(이번엔 쓰지 않음).

## 3. 퍼블릭 엔드포인트 접근 제어 수정 (updatepublicacl)

- 엔드포인트를 "프라이빗&퍼블릭" 으로 바꾼 뒤(Editing ≈2분 → Running) 라벨이 나타난다. 연필 → 모달 "퍼블릭 엔드포인트 접근 제어 수정": "사용" 체크, "퍼블릭 접근 허용 IP" 입력란(CIDR 또는 IP, 한 번에 최대 100)
  + 첫 번째 "추가" · "전체 삭제" · 추가된 IP 목록("추가할 IP 총 n/100"), "퍼블릭 접근 허용 리소스" 표 + 두 번째 "추가" → 확인 → "수정한 정보를 저장하시겠습니까?" → `PUT …/container-registries/{id}/public-acl`.
- 저장 뒤 상세 "퍼블릭 접근 허용 IP = 총 1 192.0.2.10/32"(즉시, Editing 없음). spec steps[4] 가 192.0.2.10/32 를 추가한다.

## 4. KI-001 (퍼블릭 끄기 미반영) — 2026-10-16 재현

- 퍼블릭&퍼블릭 → "프라이빗" 저장 시 `PUT …/enable-public-endpoint` 는 나가지만 2분 뒤에도 상세 "엔드포인트 = 프라이빗&퍼블릭" 그대로(10-16 15:xx·16:4x 두 번 재현). 모달 안내문 "퍼블릭 엔드포인트를 비활성화하는 경우, 설정된 엔드포인트 접근제어 리스트는 삭제됩니다."
  → spec 은 되돌림을 **마지막 단계(steps[4] 끝)** 에 두어 접근 제어 두 동작과 태그가 먼저 통과하게 했다. 결함이 남아 있는 동안 spec 결과는 FAIL(known: KI-001).
- 해지는 퍼블릭이 켜진 채로도 된다(상세 "서비스 해지" → Terminating ≈3~5분 → 소멸).
